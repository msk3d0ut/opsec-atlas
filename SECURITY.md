# Security Policy

OpsecAtlas is a static, offline-capable knowledge base with **no backend, no accounts, and no user data collection**. Any per-user state (variables, loadout, journal) stays in your browser's local storage and never leaves your device.

## Reporting a vulnerability

If you find a security issue in the **OpsecAtlas application or site** (for example an XSS in how content renders, a broken Content-Security-Policy, or a supply-chain concern), please report it privately:

- **Email:** security@opsecatlas.com
- Or open a [GitHub security advisory](https://github.com/msk3d0ut/opsec-atlas/security/advisories/new) (preferred — keeps the report private until a fix ships).

Please include steps to reproduce and the affected page or component. We aim to acknowledge within a few days. There is no paid bug bounty; credit is given to reporters who want it.

**Out of scope:** the offensive-security *content itself* (commands, payloads, methodology) is the intended, documented purpose of the project — it is not a vulnerability. Reports that a technique "works" will be closed.

## Responsible use

OpsecAtlas is an educational reference for **authorized** security testing, CTFs, labs, and research. Using these techniques against systems you do not own or have explicit written permission to test is illegal. You are solely responsible for how you use this material.
